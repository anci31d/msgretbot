# MsgRetBot

Восстанавливает удалённые **текстовые** сообщения из заданного списка обычных Telegram-групп. Сохраняет последнюю известную редакцию на 24 часа от отправки. Изображения, стикеры, голосовые и прочие медиа пока не восстанавливаются: сохраняются только тип и минимальные метаданные, без файлов и подписей.

## Режимы

- `hybrid`: Telethon читает сообщения и удаления через пользовательский аккаунт; aiogram-бот публикует уведомления.
- `userbot`: чтение и отправка через пользовательский аккаунт Telethon. В этом режиме aiogram не используется для отправки.

Обычный Bot API не предоставляет события удаления сообщений в группах. Поэтому **в обоих режимах нужен пользовательский аккаунт**, состоящий во всех отслеживаемых группах. Для `hybrid` бот также должен быть добавлен в эти группы и иметь право отправки сообщений. Privacy Mode бота не влияет на чтение: читает пользовательский аккаунт.

Супергруппы, каналы и группы, мигрировавшие в супергруппы, сейчас отклоняются. В обычных группах нет стандартных прямых ссылок на сообщения: контекст публикуется цитатами. Для будущих ссылок предусмотрен интерфейс `ContextFormatter`, для медиа — поле `kind` и отдельный слой Telegram-адаптеров.

## Установка

Python 3.12+ и Linux/POSIX (используется `flock` для защиты сессии от одновременного запуска). Работайте из корня проекта, используя локальную `.venv`:

```bash
.venv/bin/python -m pip install -e '.[dev]'
cp config.example.toml config.toml
```

В `config.toml` укажите реальные отрицательные числовые ID обычных групп и режим. ID групп в Telethon имеют отрицательный знак. Пример `-123456789` — заглушка, его нужно заменить. Пути БД и сессии разрешены только внутри текущего workspace. Один процесс на одну сессию.

Приложение читает переменные окружения:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_API_ID` | API ID приложения Telegram |
| `TELEGRAM_API_HASH` | API hash приложения Telegram |
| `TELEGRAM_BOT_TOKEN` | Токен бота, обязателен только для `hybrid` |

Получите API ID/hash своего приложения на `my.telegram.org`, токен — у BotFather. Задайте значения через окружение терминала или менеджер секретов. Приложение не загружает `.env` автоматически. Не помещайте секреты в TOML, Git или команды, публикуемые в отчётах.

## Авторизация и запуск

```bash
.venv/bin/python -m msgretbot login --config config.toml
.venv/bin/python -m msgretbot run --config config.toml
```

`login` интерактивно запросит телефон, код Telegram и, при необходимости, пароль 2FA средствами Telethon. Выполните команду самостоятельно в терминале; не передавайте эти данные агенту. Она не отправляет сообщения в группы. Команда `run` использует готовую сессию и не запускает интерактивную авторизацию.

Новые файлы данных создаются с закрытыми правами (`umask 077`). Файл сессии даёт доступ к аккаунту — храните его отдельно от Git и не передавайте третьим лицам. Приложение не меняет права уже существовавших файлов.

## Поведение

При каждом запуске для каждой группы загружаются последние **100 сообщений любого типа**, из которых сохраняются только сообщения моложе 24 часов. Чтение истории не означает восстановление уже отсутствующих в ней сообщений: восстановить можно только заранее сохранённый текст. Живые события буферизуются во время загрузки; более старая редакция из истории не заменяет более новую.

Сохранённые сообщения адресно проверяются после запуска и каждую минуту при наличии соединения — это также закрывает короткие переподключения. Запросы выполняются последовательно с интервалом не менее 0,5 секунды. Неполный ответ, ошибка сети или потеря доступа к группе дают «неизвестно», а не «удалено». При больших объёмах сверка занимает больше минуты; мгновенное обнаружение после простоя не гарантируется.

Пример уведомления:

````text
!!! ШИФРУН АЛЕРТ !!!
Сообщение @user удалено:
```
последний сохранённый текст
```
Контекст:
1. @alice: предыдущая реплика
2. @bob: ещё одна реплика
3. @charlie: более ранняя реплика
````

Telegram не сообщает достоверно, кто выполнил удаление: это может быть автор или администратор. Упоминание относится к автору. Если username отсутствует, используется имя со ссылкой-упоминанием по ID.

Контекст выбирается из 10 предыдущих сохранённых непросроченных текстовых сообщений, ещё не помеченных удалёнными: сначала ближайшие сообщения разных авторов, затем ближайшие оставшиеся до трёх цитат. Поэтому от одного участника также могут выводиться три реплики. Медиа не занимают место в окне; собственные алерты исключаются. Сообщения вне окна не рассматриваются. Автор удалённого сообщения допускается. Цитаты ограничены 160 символами и выводятся от ближайшей к более ранним; при нехватке выводятся доступные. Сообщения с неизвестным состоянием не включаются. При повторной отправке используется сохранённый снимок контекста; его актуальность в момент доставки не гарантируется.

Каждая часть алерта отправляется ответом на последнее подтверждённо существующее сохранённое сообщение перед удалённым, включая медиа. Служебные сообщения и собственные алерты не используются. Привязка проверяется перед отправкой. Если цели нет или она удалена во время отправки, алерт публикуется без reply.

Длинные тексты разбиваются на сообщения с учётом UTF-16, HTML экранируется. Исходные Telegram entities не сохраняются. Собственные уведомления не участвуют в контексте и не восстанавливаются. В `hybrid` отправитель должен быть выделенным ботом: все его сообщения исключаются. В `userbot` после потери ответа об отправке собственное уведомление распознаётся по автору и тексту подготовленной очереди.

## Хранение и отказоустойчивость

SQLite использует WAL, внешние ключи и версионируемую схему. Отметка об удалении и постановка уведомления в очередь выполняются в одной транзакции. Состояние отправки сохраняется для каждой части длинного уведомления; повторное событие удаления не создаёт дубликат задания.

Очистка выполняется при запуске и каждую минуту независимо от сетевых ожиданий. Записи старше 24 часов сразу исключаются из обработки; при очистке удаляются и связанные задания, включая неотправленные уведомления. TTL не продлевается редактированием. Это логическое удаление из таблиц, а не гарантированное физическое стирание SQLite/WAL или резервных копий. Исходные сообщения и уже опубликованные уведомления из Telegram приложение не удаляет.

FloodWait/RetryAfter приостанавливает отправку; временные ошибки повторяются через 5 секунд. Ошибки прав/назначения повторяются раз в минуту до истечения TTL. Очередь переживает перезапуск. Userbot использует стабильный `random_id` для повторной отправки одной части. При неопределённом сетевом результате, особенно через Bot API, строго однократная доставка не гарантируется. Неустранимая ошибка фонового обработчика останавливает процесс; запускать повторно можно после устранения причины.

Сообщения не могут быть восстановлены, если они не были сохранены, старше суток, удалены во время утраты доступа и не поддаются подтверждению либо Telegram не доставил необходимые события. Сессия Telethon хранит служебное состояние и кэш сущностей отдельно от БД сообщений; TTL сообщений не очищает авторизацию аккаунта.

## Логирование

В `config.toml` настройте таблицу:

```toml
[logging]
output = "stdout" # "stdout" or "file"
level = "INFO" # "DEBUG" includes context and reconciliation details
file = "logs/msgretbot.log" # Used only for output = "file"
```

Без этой таблицы используются stdout и INFO. В режиме file вывод идёт в UTF-8-файл с ротацией: основной до 5 МиБ, один архив `.1` до 5 МиБ, суммарно до 10 МиБ. Старый архив заменяется. Новые файлы создаются с правами 0600; путь должен находиться внутри workspace.

Логируются запуск/остановка, подключение, загрузка истории, сохранение и редактирование сообщений, подтверждение удаления и постановка в очередь, попытки и результаты отправки (с ID оригинала, алерта, reply и номером части), повторы/ошибки и очистка БД. DEBUG добавляет выбор контекста, события и сверку. Тексты сообщений, имена, username, токены и данные авторизации не выводятся. Исключения записываются по типу без текста исключения/traceback; подробные логи сторонних клиентов и SQLite отключены.

После изменения конфигурации перезапустите приложение.

## Проверки

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m msgretbot --help
```

Тесты используют временную SQLite и подменённые Telegram-клиенты, не обращаются к Telegram и не отправляют сообщения.

Для ручной приёмки в отдельных тестовых обычных группах: проверить оба режима, удаление автором и администратором, редактирование перед удалением, автора без username, длинный текст, контекст от разных участников, остановку/возобновление, ограничения отправки и удаление самого уведомления. Публикации агентом допускаются только по отдельному указанию пользователя.

Согласованное поведение хранится в `plan.md`; при изменении требований обновляйте его вместе с кодом.
